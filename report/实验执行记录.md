## 执行过程

1. 阅读源码和 Makefile，确认目标架构为 RISC-V，内核入口由链接脚本设定为 `0x80200000`。
2. 沿用已有 WSL Ubuntu，安装交叉编译器、QEMU 和 GDB，并保留软件版本记录。
3. 备份原始代码，将工作副本放入 `/home/a/oslab/project/lab1`；其他实验以后使用独立的 lab2、lab3 目录。
4. 执行 `make`，生成 `bin/kernel` 和 `bin/ucore.img`。
5. 启动原始配置，发现 OpenSBI 的下一阶段地址为 `0x0`，没有执行到内核。
6. 将启动命令中的 loader 参数改为 `-kernel bin/ucore.img` 进行单独验证，确认下一阶段地址变成 `0x80200000`，启动文字出现。
7. 在工作副本的 Makefile 中对 `qemu`、`debug` 两个目标做同样的参数兼容调整。
8. 使用 GDB 在 `kern_entry`、`kern_init` 设置断点，验证进入 C 函数前栈指针等于 `bootstacktop`。
9. 复制源码到独立提交暂存目录，在没有既有编译产物的情况下重新编译并启动成功，随后打包源码、说明与日志。

实际内核输出：

```text
(THU.CST) os is loading ...
```

运行验证达到预期输出后，用超时机制主动结束 QEMU。日志末尾的 termination 信息来自主动结束；内核源码本来就在打印后进入无限循环。
仓库里的 `boot.log` 删除了 OpenSBI 字符画中的一个 NUL 字节，以便 GitHub 按文本显示；启动地址和内核输出内容未改动。
GDB 日志来自 lab1 原工作目录的实际调试。提交暂存目录重新生成的 `ucore.img` 与该工作目录镜像的 SHA-256 一致。

## 修改范围

原始 C、汇编、头文件和链接脚本保持不变。Makefile 仅调整两处 QEMU 参数；补丁位于 `records/environment-compatibility.patch`。
Ubuntu 提供 `gdb-multiarch`，本机用兼容符号链接支持原 Makefile 的 `make gdb`；提交包 README 也给出直接调用 `gdb-multiarch` 的方法。

QEMU 官方文档说明 `virt` 平台可以配合默认 OpenSBI 使用 `-kernel` 启动方式：[QEMU virt — Boot options](https://www.qemu.org/docs/master/system/riscv/virt.html#boot-options)。本次调整已在本机实际验证。
