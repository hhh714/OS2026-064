## 一、实验目标与 AI 协作分工

本实验在 Lab2 内存管理的基础上建立完整的 Trap 处理闭环：处理器产生 Trap 后，由汇编保存现场，将现场传给 C 语言处理函数，再根据处理后的现场恢复寄存器并通过 `sret` 返回。

学生负责分析实验要求、确定修改边界、描述前置条件与后置效果、理解关键代码并运行验证；AI 负责根据这些规格补全实现、解释代码及辅助定位错误。是否满足要求，最终依据代码核验、测试断言及 QEMU 运行结果判断。

本次分为两个职责闭合的实现任务：

1. 上下文恢复与 Trap 入口：解决“现场如何交给 C 函数，以及如何恢复”。
2. 中断与异常处理：解决“进入 C 函数以后如何处理原因并返回”。

Lab2 的物理内存初始化和 Best-Fit 是启动依赖，单独承接，避免把内存分配算法与 Trap 新功能混为一个任务。

## 二、整体实现逻辑与修改范围

### 2.1 运行链路

```text
内核启动及内存初始化
  -> idt_init() 设置 stvec，指向 __alltraps
  -> 时钟初始化及中断使能，或执行触发异常的指令
  -> 处理器记录 sepc、scause、stval，并更新 sstatus
  -> __alltraps / SAVE_ALL 构造 TrapFrame
  -> trap(tf) -> trap_dispatch(tf)
       -> interrupt_handler(tf)
       -> exception_handler(tf)
  -> __trapret / RESTORE_ALL
  -> sret 返回
```

硬件记录 Trap 控制状态，但不会自动替软件把全部通用寄存器压入内核栈。通用寄存器现场由 `SAVE_ALL` 保存；处理函数对 `tf->epc` 的修改会由恢复流程写回 `sepc`。

### P — Prompt：任务说明

请实现 Lab3 的 Trap 上下文恢复与汇编入口模块，使系统能够完成“保存现场、进入 C 处理函数、恢复现场、返回原执行流”的闭环。

修改 `kern/trap/trapentry.S` 中 `RESTORE_ALL` 以及 `__alltraps` 的 Lab3 预留位置，保留 `lab3` 标签，将对应 `YOUR CODE` 替换为 2414077。不得修改 `SAVE_ALL` 的保存顺序、`struct trapframe` 的布局和 `trap()` 的函数签名，不改测试、链接脚本或其他模块。

请先依据现有保存逻辑确认现场布局，再给出实现。输出修改说明、恢复顺序的理由，以及如何验证通用寄存器、栈指针和返回位置恢复正确。若发现工具链兼容问题，应指出具体错误及最小兼容方案，不通过改变现场布局绕过问题。

### R — Rely：最小依赖

- `kern/trap/trapentry.S`：现有 `SAVE_ALL`、`RESTORE_ALL`、`__alltraps`、`__trapret`。
- `kern/trap/trap.h`：`struct pushregs` 和 `struct trapframe`。
- `libs/riscv.h`：`REGBYTES`、`LOAD`、`STORE` 和相关 CSR 定义。
- C 接口 `void trap(struct trapframe *tf)`。
- RV64 函数调用约定及 `sret` 的返回机制。

### G — Guarantee：接口清单

| 交付点 | 输入状态 | 对外结果 |
| --- | --- | --- |
| `RESTORE_ALL` | `sp` 指向现有布局的 TrapFrame | 恢复可写通用寄存器、`sstatus`、`sepc` 和原 `sp` |
| `__alltraps` | 处理器跳至 Trap 入口 | 保存现场并把当前帧指针作为参数交给 `trap()` |
| `__trapret` | C 处理函数返回，栈仍指向现场 | 恢复后执行框架中的 `sret` |

### S — Specification：行为规格

1. **布局一致性**：以现有 `SAVE_ALL` 和结构体为准。RV64 下 36 个槽各占 8 字节，共 288 字节；通用寄存器按编号对应槽位，槽 32～35 分别是状态、EPC、异常相关地址和原因。
2. **栈指针恢复**：槽 2 保存的是 Trap 前的 `sp`。在其他恢复操作仍需要当前帧地址时，不得提前恢复它；完成其他必要加载后再恢复原 `sp`。
3. **寄存器完整性**：恢复所有已保存的可写通用寄存器，包括被用作临时变量的寄存器；`x0` 固定为零，不需恢复。
4. **控制状态**：恢复 `sstatus`，将帧内的 EPC 写回 `sepc`。允许 C 处理函数按异常语义修改 EPC；`scause` 和 `stval` 是诊断信息，不要求当作返回现场写回。
5. **参数传递**：`trap()` 接收到的指针必须是当前保存帧的起始地址，按调用约定通过 `a0` 传递。C 函数返回后，恢复代码仍须能访问原帧。
6. **返回闭环**：C 函数返回后进入统一恢复路径，由 `sret` 完成 Trap 返回，不能使用普通函数返回代替。
7. **栈对齐**：在入口栈符合 ABI 对齐的前提下，分配现场后调用 C 函数仍保持 16 字节对齐。
8. **验收**：用框架测试验证断点 Trap 能进入 C 函数，返回后寄存器与预设值一致、`sp` 恢复正确，并从更新后的 EPC 继续执行。不得删除断言或只打印通过信息。

## 六、实际问题与提示词迭代

### 6.1 已实际出现：工具链不识别旧 CSR 名称

第一次编译在 `trapentry.S` 中失败：

```text
Error: unknown CSR `sbadaddr'
Info: macro invoked from here
```

原因是框架使用旧名称 `sbadaddr`，当前汇编器不接受该名称；对应 CSR 的现代名称是 `stval`，编号为 `0x143`。这不是 TrapFrame 偏移错误。

实际修复是在文件顶部提供条件宏，将 `sbadaddr` 映射到已有的 `CSR_SBADADDR` 数值定义。`SAVE_ALL` 的指令文本、保存槽位和结构体布局保持原有关系。

**针对该错误的补充提示词：**

> 当前编译在已有 `SAVE_ALL` 中报 unknown CSR `sbadaddr`。请检查框架 CSR 定义和工具链可接受的写法，用最小兼容修改解决名称问题。不得改变现场布局、寄存器保存顺序或删除异常地址保存。解释旧名称与现代名称的对应关系，并重新通过原有构建和 Trap 测试验证。

### 6.2 实现时发现：关机阈值宏缺失

实验要求提到 `SHUTDOWN_AFTER`，实际框架未提供该定义。代码补充了默认值 10，并用 `#ifndef` 允许外部配置覆盖。该情况是依赖检查中发现的缺项，不记为已经发生过的编译报错。

默认普通运行在输出 10 次 `100 ticks` 后关机，即累计处理 1000 次时钟中断。打印的是每个统计周期的固定文字，不能把每一行都理解为总计只有 100 次。

### 6.3 人工重点核验，但没有记录为实际故障的问题

| 风险 | 核验方式 |

## 八、重要知识点与 OS 原理的联系

| 知识点 | 原理含义 | 本实验对应及区别 |
| --- | --- | --- |
| Trap、中断与异常 | Trap 统称控制转移；中断通常异步，异常由当前执行同步触发 | 根据 `scause` 最高位区分，再按原因编号分派 |
| 中断现场 | 保存恢复后继续运行所需的状态 | TrapFrame 保存通用寄存器和 CSR 快照；硬件不会自动保存整帧 |
| 调用约定 | 规定函数参数、栈及寄存器使用规则 | `a0` 传帧指针；Trap 必须恢复完整被打断现场，不能仅按普通 C 函数保存规则处理 |
| 异常返回地址 | 决定处理完成后的执行位置 | `tf->epc` 写回 `sepc`；本实验对指定异常跳过触发指令，其他异常可能需要重试或终止 |
| 特权状态恢复 | 返回时恢复前一执行级别和中断状态 | `sret` 依据 `sstatus` 的相关状态返回，不等同于普通 `ret` |
| 时钟中断 | 为时间管理和调度提供周期事件 | 本实验重设事件并计数，尚未实现进程时间片切换 |
| 机制与策略 | 入口、保存恢复提供机制，处理函数决定行为 | 统一汇编入口与不同 C 处理分支分工 |
| 临界区 | 防止并发进入破坏共享状态 | 继承 Lab3 内存分配的本地中断保护；关闭本地中断不等于解决多核互斥 |

本实验源代码部分历史注释包含 x86 的 IDT、iret 或 8253 等术语；理解本次 RISC-V 实现应以实际的 `stvec`、`sret` 和 SBI 时钟接口为准。

## 九、本实验未覆盖的重要知识点

1. **进程调度与完整进程切换**：时钟是调度基础，但打印 ticks 并不等于切换进程。
2. **用户态系统调用**：本次以内核环境为主，未建立完整用户栈、系统调用参数校验与安全访问机制。
3. **缺页处理和按需分页**：可打印相关异常现场，但未实现分配页面、更新映射后重试故障指令的流程。
4. **外设驱动与中断控制器**：分类输出外部中断不等于完成设备确认、清除中断和驱动处理。
5. **嵌套中断、多核同步和可重入性**：现有测试不能证明这些复杂情形正确。
6. **浮点/向量扩展上下文**：当前帧主要保存整数寄存器与相关 CSR，未实现完整扩展寄存器现场管理。
7. **通用异常恢复**：当前 EPC 长度判断依赖可读内核代码，不能直接作为任意用户地址或取指故障场景的安全恢复方案。
